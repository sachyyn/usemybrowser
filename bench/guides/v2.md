# Tool for this run: umb

Use ONLY the `umb` command (via Bash) to work in the user's real, running browser. It is on your PATH. Do not use any other browser tool. Never run `umb start` or `umb stop`.

## Commands

- `umb open <url>` opens a new background tab and prints `<tab id> "title" url`. Use that id as `<tab>` below.
- `umb tabs` lists tabs. `umb close <tab>` closes one.
- `umb snap <tab> [--find <regex>] [--interactive] [--within <css>] [--delta] [--max <n>]` prints a compact outline of the page. Lines for elements you can act on start with a ref such as `e12`. Refs stay the same across snaps while the element is the same. `--find` filters the outline and also lists matching plain visible text as `text "..."` lines. `--delta` prints only what changed since the last snap. `--interactive` lists only controls.
- `umb click <tab> <target> [--force]` and `umb fill <tab> <target> <value>`. A target is a ref (`e12`), exact visible text (`text:"Add Filter"`) or a selector (`css:"button.save"`). Each prints one line saying what changed. A click fails if the target is covered (it names what is on top), missing, or matches more than one element. `fill` sets inputs, textareas, selects and checkboxes (`true`/`false`) and confirms the value stuck.
- `umb wait <tab> [--text s] [--gone s] [--url s] [--ref eN | --css sel] [--timeout ms]`.
- `umb text <tab> [css selector] [max chars]` prints plain text of part of the page.
- `umb run <tab> <file.js | -> ['<json args>'] [--max n]` runs one script in the page. The script is the body of an async function and what it returns is printed. In scope: `args`, and `umb.find(target)`, `umb.click(target)`, `umb.fill(target, value)`, `umb.wait(fn, timeoutMs)`, `umb.sleep(ms)`, `umb.text(css, max)`, plus the normal page `document` and `window`. One script can do many steps; a navigation ends it.
- `umb recipe` lists saved recipes; `umb recipe <name> '<json args>'` runs one.
- `umb check <tab> "<yes/no question>"` answers a visual question about the page without you seeing the image.

## Real keyboard input, many steps in one command

`click`, `fill` and `run` act through page JavaScript. Some apps ignore that for typing, for example grids drawn on a canvas (Google Sheets). For those use real input:

- `umb keys <tab> <step>...` runs a sequence in ONE command and stops at the first failure. Steps: `click:<target>`, `type:<text>` (short text only), `paste:<text>` or `paste:@<file>` (delivers a whole block to the focused element in one step, in about 3 seconds), `clear` (empties the focused input), `key:<Key or Combo>` (e.g. `key:Enter`), `wait:<ms>`. Example: `umb keys 7 'click:css:#t-name-box' 'type:A1' 'key:Enter' 'paste:@data.tsv' 'key:Enter'`.
- Blocks of cells go in with `paste:@file`: write the block as a tab-separated file (formulas such as `=E2*F2` included, one row per line) and paste it at the top-left cell. A whole 41 x 8 block is one paste. Do not type cells or formulas one at a time: the app's suggestions corrupt typed formulas, and typing is slow.
- Data you were given should be written to a file once and pasted. Do not retype it in commands.
- To replace the text in an ordinary input use `fill`, or `click:<target>` then `clear` then `type:`. `key:Meta+A` does not select text in ordinary inputs.

## Proof in the same call

`click`, `fill`, `keys`, `run` and `recipe` take flags that are checked after the action, so you do not need a second command to look:

- `--expect <text>`, `--expect-gone <text>`, `--expect-url <part>` (visible page text or the URL; not text on a canvas).
- `--read <css> [--read-max n]` prints that part of the page as text after the action.

## Seeing the page without loading images

A screenshot you open yourself is the most expensive thing you can do: avoid it. In order of preference:

1. Read text: `umb text`, `umb snap --find`, `--read`.
2. Google Sheets (cells are on a canvas): `umb recipe sheets-read '{"sheet":"Data","range":"A1:H5"}' --tab <tab>` returns cell VALUES as tab-separated lines (a text cell in a mostly numeric or date column, including its header, and error cells can come back empty: that is the reader, not the sheet). `umb recipe sheets-formula '{"cells":["Data!G2","Summary!B9"]}' --tab <tab>` returns the formula or typed value of single cells (about 2.2 s per cell, so ask for a few sample cells, not whole ranges; it moves the selected cell).
3. `umb look <tab> "<question>" [--region <target>]`: a small vision model looks at the page and answers in one or two lines. Use it for coarse visual questions only: "is the header row bold?", "is there a chart, and what type?", "what does the open dialog say?". Do NOT use it to read cell values or to decide whether cells are empty: it misreads dense grids. Cell values come from `sheets-read`, formulas from `sheets-formula`.
4. `umb check <tab> "<yes/no question>"` for a plain yes/no.
5. Only if all of that fails: `umb shot <tab> [--region <target>]` saves a small cropped image and prints its path for your image reader.

## Working cheaply

Every turn you take costs about as much as everything the tool prints in that turn, so take fewer, bigger turns.

- When `umb open` prints a `notes:` line, run that `umb notes <host>` command first. It lists proven one-line ways to do common jobs on that site. Use them instead of exploring menus.
- Plan the whole job, then do each sub-goal as ONE Bash call that acts and proves the result (chain commands with `&&`, use `--expect` and `--read`, end with one read-back).
- Prefer one `umb keys` or `umb run` for a multi-step action over many single commands.
- Read the smallest thing that answers the question.
- When the job is done, save what non-obviously worked on this site, one line each, at most five: `umb note <host> "<one command line and when to use it>"`. `umb notes <host>` shows them next time. Skip what the page makes obvious.
- A command that ran is not proof. Before you report, read back the values that matter, and read a dialog's fields back before you press its Done or Save button.
